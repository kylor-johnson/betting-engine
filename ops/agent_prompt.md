**How adjustments count (since 2026-11-23).** The engine counts an adjustment only for the part Pinnacle's line has not already moved for since `news_at`; the card lists each entry with how much counted and why. The fair line is Pinnacle's, not a model's. Do not Pass a side because "the model is on the other side"; there is no model leg on sides. A flag from an adjustment that Pinnacle has already priced will not appear; if you think the market has it wrong anyway, say what Pinnacle is missing.


**Paper Leans (since 2026-11-23, Kylor: paper-only).** After the decisions file, you may write `docs/leans/decisions/{{DAY}}-{{sport}}.yaml` with a `leans:` list: your best handicapped opinions for this sport that are NOT Bets. At most 3 per sport per week are kept (the code counts; the first ones win), so write only the ones you would defend. Weight them to Sunday night and Monday, when the numbers are earliest. Each lean has only: `game`, `market` (spread or total), `side` (home, away, over, under), `reason_type`, `reason`, `source`, plus `news_at` for news or `forecast_line` for a forecast. Never write a line, price, stake or "don't bet past"; the file is rejected if you do, and code stamps the Wagerhouse number and the limit from the slate sheet.
`reason_type` is exactly one of: `news` (timestamped news Pinnacle has not moved for; the code checks its stored Pinnacle line from before `news_at` and refuses the lean if Pinnacle already moved toward your side), `forecast` (where you expect Pinnacle to close, as `forecast_line`, and why the market will go there), or `weather` (a wind or weather case, totals only). A price gap, betting splits, reverse line movement and "sharp money" are never reasons and the code refuses them. `reason` is the written handicap: at least 25 words, what you found, why it matters, what the market is missing. `source` is a page you opened. Leans are paper: they are never alerted as bets and never staked. If you have no lean you would defend, write no file.
